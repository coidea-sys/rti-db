Scene 1 / flaky 测试根因

两个样本撞了同一个纳秒，scan silently 丢掉了一条

测试在紧循环里用 now_ns() 给 5 条消息打时间戳；纳秒时钟两次返回同一值 → collect_into 排序后按 ts 去重 → scan 只返回 4 条 → 断言 a.len() == 5 间歇性失败。 修复：测试改用严格递增的 mono_ts()。点播放看两条路径的对比。

Scene 2 / macOS 全特性构建

一个 Linux-only 的 import 让 --all-features 在 macOS 上炸掉

wal_bench.rs 无条件引用只在 Linux 存在的 rti_wal_uring； macOS 上开 io-uring 特性编译示例即 E0433。库里其它代码本就有 cfg(target_os = "linux") 门控，只有示例漏了。修复：补上同样的门控，非 Linux 平台优雅降级为只跑 std 后端。

Scene 3 / 门面再导出

README 的 Quickstart 声称单依赖，实测 4 个编译错误

rti-db 门面没有 re-export rti_core 的类型， 用户被迫同时依赖 3 个 crate 并理解内部拆分。修复：门面补全 pub use rti_core::{…} / rti_query::{Agg, Pred} / rti_store::{ColdTier, LocalFsColdTier}， 内部 crate 拆分回归为实现细节。
